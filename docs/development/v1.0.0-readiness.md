every release-blocking contract on the 1.0.0 candidate, the blocker classification,
and the rules for the release decision. It deliberately contains no per-run
identifiers of the final candidate: writing them here would change the candidate
commit and invalidate the evidence. The exact candidate SHA, the CI and
release-artifacts run IDs, the package digests and the attestation IDs are posted as
the final audit comment on Issue #35. This document stays structurally complete
before that evidence exists.

## Public API Freeze

Issue #45. The public API snapshot and the stable-API contract tests pass on the
candidate with no snapshot change: 23 tests. The stable surface is `pysh.api`
(`ShellSession`, the contract protocols, `PLUGIN_API_VERSION`); `pysh.shell.PyShell`
is deprecated with a warning on symbol access and is not removed before 1.2.0. The
package, Plugin API (1.0), isolated manifest (1) and IPC protocol (1) versions are
independent domains; the one test that hard-coded the package version now derives
it from `pyproject.toml`. Result: CLEAN.

## Architecture Boundaries

Issue #46. The import-boundary test enforces `architecture.toml`: 20 tests pass, no
exceptions were added for this audit. Result: CLEAN.

## Security and Threat Model

Issue #43. 41 trust-model tests pass: safe `--no-rc` startup, the redaction and
diagnostic emission policy, and the STRIDE threat register. The documented
residuals are accepted limitations (trusted configuration, plugins and `py` are
trusted code; no unresolved high-severity finding). Release signing is keyless OIDC
with no long-lived private key. Result: CLEAN.

## Rollback and Yank Strategy

Published versions are immutable. The authoritative policy is in
[release.md](release.md#incident-yank-and-rollback-policy): an incomplete GitHub
Release is not a complete release and is repaired through the documented hotfix
path; a defective published PyPI 1.0.0 is never overwritten, is yanked where
appropriate and replaced by a new patch release (normally 1.0.1); a compromised
release disables the affected distribution path, reviews and rotates trust material
where applicable, publishes incident guidance and never silently substitutes bytes.
